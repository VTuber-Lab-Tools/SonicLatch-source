## ログや画像を添付する前に

添付は任意です。まず文章だけでも状況を報告できます。音声データ（PCM を含む）、配信・録画ファイル、ストリームキー、パスワード、トークンは送らないでください。シーン一式やクラッシュダンプもこのテンプレートでは求めません。

1. 元のログを手元に残し、共有用のコピーを作ります。問題の前後に絞り、無関係な内容を省きます。
2. コピーをテキストとして開き、全文を確認します。ソース名、シーン名、UUID、ユーザー名を含むファイルパス、メールアドレス、URL の認証情報などが含まれていないかを探します。例外メッセージの中も確認してください。
3. 識別情報は「[ソースA]」「[UUID-A]」「[非公開パス]」などに置き換えます。同じ対象は同じ仮名にし、別の対象には別の仮名を使います。エラー名・状態・数値・発生順は、秘密情報を含まない範囲で残してください。
4. 画像は必要な範囲に切り抜き、配信プレビュー、チャット、アカウント名、ソース名、パスなどを不透明な塗りつぶしで隠します。書き出した画像を開き直し、隠した情報が見えず、必要な状態表示は読めることを確認します。
5. ファイル名にも個人情報がないか確認し、共有する最終ファイルをもう一度読みます。安全に除去できるか迷う場合は添付せず、状況を文章で記入してください。

自動マスク済みとは考えず、手動で確認してください。現時点で製品内の問い合わせ用ログ書き出し・プレビュー・自動マスク機能は確認されていません。ログに記録されない状態もあるため、該当行が見つからなくても、画面の状態と再現手順を記入してください。

## 操作・状態を報告するとき

- ソース選択、PRE / POST 波形、推定遅延 D、現在の同期オフセット S、推定残差 D+S のうち、どこで問題が起きたかを書いてください。画面にない値は推測しないでください。「—」は 0 ms ではなく、値が得られていない状態です。
- 「自動調整（Auto）」は有効な推定遅延 D に対し S=−D に設定します。現在値へ加算する操作でも、連続追従でもありません。±、数値入力後の「入力したオフセットを適用」、「元に戻す」、「補正リセット」も製品操作です。「補正リセット」は 0 ms で、導入前への復元ではありません。
- 「元に戻す」は直前に成功した変更の前へ戻します。対象や設定の変更等で無効になる場合があります。外部からのオフセット変更で無効になった Undo は、現在値を読み直しても復活しません。無効なボタンを有効にするための連打はしないでください。
- 表示上の POST 位置や推定残差は補正後の出力を再測定した結果ではありません。録画での問題なら、画面だけの問題と区別して文章で説明してください。録画そのものの送付は不要です。
- 導入・更新・削除・復旧の問題では、実行ファイル名、操作の順序、完了か中断か、表示エラーを追加してください。保護設定の解除、アクセス権の変更、管理用記録やバックアップの削除はしないでください。

## 配布前候補について

製品の Auto・手動調整・Undo・Reset は既存の限定検証で確認済みです。対象環境は Windows 64-bit、OBS 30以上（OBS 32.2.2推奨）です。最新候補は OBS 32.2.2 向けの SDK/API 32 でビルドされ、実機で読み込み・ドック表示を確認しています。2026-10-20 の実機確認では、最新 Setup の OBS 起動中の停止と再インストールに問題がないとの報告があります。OBS 30 / 31 の実機動作は未検証です。対応環境と検証範囲は同梱の「検証環境と現在の制限」を参照してください。この文書の完成を、正式配布や全導入・削除・復旧経路の確認完了とは扱わないでください。
