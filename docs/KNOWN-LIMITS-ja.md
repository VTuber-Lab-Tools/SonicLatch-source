# SonicLatch：検証環境と現在の制限（公開前候補）

対象環境は Windows 64-bit、OBS 30以上（OBS 32.2.2推奨）です。OBS 32.2.2 の実機で読み込み・ドック表示を確認しています。OBS 30 / 31 の実機動作は未検証です。対象表記と検証済み範囲は区別してください。

2026-10-20 の保存済み証拠と、その後の同日の実機確認報告に基づきます。製品の対象と、実際に確認した候補・条件は別です。最新 Setup の OBS 起動中の停止と再インストールは問題なしとの報告があります。これを全導入・削除・中断復旧経路の確認完了や OBS 30 / 31 の検証済み表示へ一般化しません。

## 測定・調整の限界

- 無音、ミュート、無効入力、音の内容やフィルター処理により測定値が得られない場合があります。「—」は 0 ms ではありません。有効な新しい推定を待ち、状態を確認してください。再選択や再読取りは万能な復旧策ではありません。
- 推定遅延 D は PRE / POST の比較から求めます。現在の同期オフセット S を反映した POST の位置と D+S はモデル上の推定で、補正後出力の再測定ではありません。OBS の値の読戻しも、録画同期が成立した証明ではありません。
- Auto は有効な D に対し S=−D を明示クリック時に設定する操作です。連続追従ではなく、設定後や配信中にもズレは変動し得ます。新たな有効推定を確認して再設定できますが、完全一致は保証しません。
- ± や入力適用は同期オフセットを変更します。Undo は直前の成功操作前へ戻し、Reset は 0 ms にします。外部変更などで Undo が無効になる場合があります。読み直しで Undo を復活させることはできません。
- 録画についても独立 marker / 基準 track による既存確認があり、成功ケースだけでなく失敗・限界も確認されています。「録画は一切未検証」でも「常に完全同期」でもありません。環境・処理状況により完全一致しない場合があります。
- カメラを含む映像経路全体の測定、自動リップシンク、モニター音声の遅延解消、フィルター処理時間そのものの除去は対象ではありません。同じ音声ソースを複数シーンで使う場合、同期オフセット変更はそれらにも影響します。

## 保全する既知記録

- 旧 API 33 DLL（0b59 系）は OBS 32.2.2 で newer libobs 33.0 を理由に −4 で拒否されました。この旧記録は保全し、現在の API 32 DLL の読み込み結果とは区別します。
- 終了時の OBS メモリー診断カウンターが 1 となる旧記録があり、対象 DLL なし／ありの比較でも両方 1 でした。割当元は未特定です。製品固有のリークとも、リークなしとも断定しません。確認済みの回避策はありません。
- 旧負荷試験の基準超過は原因未特定のままです。後続の固定条件での通常／負荷 600 秒 PASS は存在しますが、旧原因の修正証明や全コールバックの最大時間保証ではありません。これは旧記録の保全であり、今回リリースに追加の長期再試験を要求するものではありません。
