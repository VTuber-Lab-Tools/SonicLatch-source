# SonicLatch の使い方

本書は配布準備中の手順です。2026-10-20 の実機確認では、最新セットアップの OBS 起動中の停止と再インストールに問題がないとの報告があります。確認済みの範囲は同梱の KNOWN-LIMITS-ja.txt を参照してください。

## 導入

1. 配布ページで Windows 用セットアップとして案内されている EXE を取得します。ソースコード ZIP は通常の導入用ではありません。配布ページの対象版と対応環境を確認してください。
2. 配信・録画を終了し、起動している OBS をすべて終了します。
3. 取得したセットアップを起動します。Windows の管理者確認が表示されたら、起動したファイルを確認して本人が許可します。許可できない場合は導入を中止してください。Windows が実行をブロックする場合は保護設定を変更して回避せず、下記窓口へお問い合わせください。
4. セットアップ画面の案内に従って導入します。現在のセットアップ画面は日本語です。導入先を選ぶ画面はなく、Windows 共通データフォルダー内の obs-studio\plugins\SonicLatch に配置されます（通常は C:\ProgramData\obs-studio\plugins\SonicLatch）。DLL はその中の bin\64bit\SonicLatch.dll、言語・ヘルプは data に配置されます。OBS のプログラムフォルダーを指定したり、DLL をプラグイン直下へ手動コピーしたりする必要はありません。
5. 完了が表示されたら OBS を起動し、「ドック」メニューから「遅延補正(SonicLatch)」を開きます。表示されない場合は手動コピーや繰り返し導入をせず、OBS の版と下記の対応条件を確認してお問い合わせください。

導入が完了しなかった場合は、次の「中断・エラー時」を参照してください。ポータブル構成や独自のプラグイン配置先への導入は、この手順の確認対象ではありません。

## 更新

OBS をすべて終了してから、配布ページでお使いの版からの更新に対応すると明示されたセットアップを実行します。更新対応が記載されていない旧版や、手動で配置した版は、上書き・先行削除せず窓口へお問い合わせください。旧版用のファイルを新しい版に混在させないでください。

## 削除

1. SonicLatch で設定した同期オフセットを不要にする場合は、削除前に OBS で対象ソースの現在値を確認し、必要に応じて「補正リセット」または手動調整を行います。「補正リセット」は 0 ms にする操作で、導入前の値への復元ではありません。プラグインの削除による同期オフセットの自動復元は前提にしないでください。
2. 配信・録画を終了し、起動している OBS をすべて終了します。
3. Windows のアプリ一覧で「SonicLatch」を選び、アンインストールを開始します。管理者確認を確認し、削除画面の案内に従います。
4. 削除完了後に OBS を起動し、使っているソースの同期オフセットと実際の音声を確認します。

アプリ一覧に SonicLatch がない、または削除が中断した場合は、手動で関連フォルダーを消さず、次の「中断・エラー時」を参照してください。

## 中断・エラー時

- OBS の終了を求める画面が出た場合、OK を押すとセットアップは終了します。配信・録画を終了して OBS をすべて閉じた後、同じセットアップを新しく起動してください。中断した画面のまま待っても導入は再開しません。
- 導入で「中断記録から復旧しますか？」と表示された場合は、OBS を終了した状態で画面の復旧操作を使います。削除時の「記録から復旧しますか？」も同様です。
- 「中断前の状態へ戻しました」と表示された場合は、導入・削除の完了ではありません。画面の案内に従い、同じセットアップまたは同じアンインストーラーを再度実行してください。
- 「前回のアンインストールの後片付けが完了しました」と表示された場合も、新しい導入は完了していません。導入する場合に限り、画面の案内に従って同じセットアップを再度実行します。
- エラーで終了した場合はファイルを残し、同じセットアップ、または削除に使用した同じアンインストーラーで案内される復旧を使ってください。復旧しても進めない場合やアプリ一覧にない場合は、繰り返し実行せずお問い合わせください。管理用の記録やバックアップを消したり、フォルダーのアクセス権を変更したりしないでください。
- お問い合わせ先は [SonicLatch の GitHub Issues](https://github.com/VTuber-Lab-Tools/SonicLatch-source/issues) です。OBS の版、SonicLatch の版、実行したセットアップのファイル名、操作手順、表示されたエラーを添えてください。ログや画像は、氏名・ユーザーフォルダー名などの個人情報や秘密情報を確認し、必要箇所だけを共有してください。

## 測る → 波形を確認 → 調整する

1. 確認したい音声ソースを選び、音声を入力します。
   処理前の音声を取得する測定用フィルター「音声遅延測定（SonicLatch）」が自動で追加されます。手動追加は不要です。使用中は削除・無効化・順番変更をしないでください。
2. PRE（フィルター前）/ POST（フィルター後）の波形と推定遅延、状態表示を確認します。
3. 推定が有効になったら「自動調整（Auto）」で、測った遅れを打ち消す値に設定します。
4. 必要に応じて ± または数値入力で調整します。数値を入力・編集しただけでは適用されません。「入力したオフセットを適用」で反映します。
5. 実際の録画・配信で音声を確認します。直前の操作を戻すには「元に戻す」、オフセットを 0 ms にするには「補正リセット」を使います。

PRE / POST の比較から遅延 D を推定し、表示では POST 波形を現在の同期オフセット S だけ時間方向へずらします。この表示は補正後出力の再測定ではありません。

## 各操作の意味

- 自動調整（Auto）: 有効な推定遅延 D に対し、同期オフセットを −D に設定します。現在値への加算ではありません。
- ±: 現在の同期オフセットを基準に調整します。
- 数値入力: 指定した同期オフセットに設定します。
- 元に戻す: 直前に成功した操作の前の値へ戻します。ソースや外部オフセットの変更などで利用できなくなる場合があります。
- 補正リセット: 同期オフセットを 0 ms にします。
- 残差: 推定遅延 D と同期オフセット S の合計 D + S を表示します。補正後出力の実測値ではありません。

例えば D が +80 ms なら、Auto は現在のオフセットにかかわらず −80 ms に設定します。

OBS の詳細音声プロパティでも現在の同期オフセットを確認できます。外部で値やソースを変更した後は、現在の状態と新しい有効な推定を確認してから操作してください。

## 環境による変動と再調整

環境や処理状況によって、音声が完全に一致するとは限りません。配信中や設定後にも推定値・音声の遅れが変動する場合があります。ズレが気になったときは、入力と有効な推定を確認して「自動調整」を再度押すことで、その時点の推定に基づいて調整し直せます。継続的に自動追従する機能ではなく、完全一致を保証するものでもありません。

## 範囲と表示

対象環境は Windows 64-bit、OBS 30以上（OBS 32.2.2推奨）です。OBS 32.2.2 の実機で読み込み・ドック表示を確認しています。OBS 30 / 31 の実機動作は未検証です。対象表記と検証済み範囲は区別してください。

音声設定はステレオ、サンプルレートは 44.1 kHz または 48 kHz が対象です。

推定遅延 D の測定範囲は約±500 ms未満（探索端を除外）、同期オフセット S の書き込み範囲は −950〜+1000 ms です。測定範囲と書き込み範囲は異なります。

測定・表示だけでは同期オフセットを書き換えません。無音、ミュート、無効な推定などの場合は、入力と状態表示を確認してください。

## ヘルプの場所

16言語のヘルプは、上記 SonicLatch フォルダー内の data\help\guide-言語コード.txt にあります。同じhelpフォルダーに日英の導入手順 USAGE-ja.txt / USAGE-en.txt を同梱します。OBSの表示言語を変更した後は、OBSを再起動してください。

同梱helpフォルダーの SUPPORT-ja.txt と KNOWN-LIMITS-ja.txt を参照してください。問い合わせ先はSonicLatchを扱うBOOTHショップのメッセージです。対応言語は日本語・英語です。
